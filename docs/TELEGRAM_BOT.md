# Telegram commerce-бот ProxyHarbor

## Что реализовано

Основной бот является частью ProxyHarbor API и управляется на `/admin/telegram`. Этот же бот отправляет резервные копии: отдельный BotFather token и ручной `chat_id` для backup не нужны. В разделе `/admin/backups` получатель выбирается среди пользователей, уже написавших боту; `@Xsenus` предлагается первым и используется как стандартный администратор.

- автоматическая проверка token через `getMe`;
- автоматическая установка имени, полного и короткого описания, изображения ProxyHarbor, команд и кнопки меню;
- webhook с `X-Telegram-Bot-Api-Secret-Token` либо long polling; одновременно работает только выбранный режим;
- команды `/start`, `/account`, `/buy`, `/proxies`, `/notifications`, `/language`, `/support`, `/help`;
- меню, кабинет, покупка, уведомления и системные ответы на русском, английском, немецком, французском и упрощённом китайском; при первом запуске используется поддерживаемый язык Telegram, после `/language` выбор сохраняется в общем профиле аккаунта;
- единый каталог оплаты: после выбора тарифа бот показывает Telegram Stars и все включённые, полностью настроенные шлюзы из `/admin/payments`;
- Telegram Stars invoices в валюте `XTR`, проверка `pre_checkout_query` и идемпотентная активация подписки только после `successful_payment`;
- для ЮKassa, ЮMoney, CloudPayments, Robokassa, Т-Банка, Stripe, Cryptomus и NOWPayments бот создаёт обычный серверный заказ и выдаёт HTTPS-кнопку на hosted checkout; реквизиты в Telegram не вводятся;
- личный кабинет со статусом/сроком подписки, общим количеством оплат, потраченными Stars и выданными файлами;
- TXT-файл только из свежих Alive-прокси и только при активной подписке;
- напоминания за 7, 3 и 1 день, уведомление об окончании и автоматическое снятие роли Subscriber;
- базовые ответы на частые вопросы и сохранение входящих обращений в CRM;
- личные ответы и массовая рассылка из админки;
- персистентная PostgreSQL-очередь, lease, повтор после `retry_after`, exponential backoff и лимиты 25 сообщений/с глобально и 1 сообщение/с на чат;
- блокировка дальнейшей доставки после Telegram `403`, дедупликация update и платежей;
- резервное копирование конфигурации, CRM, очереди и обработанных update.
- доставка PHB3-архивов выбранному активному CRM-диалогу с актуальным token основного бота на момент отправки.

## Подключение

1. В Telegram откройте `@BotFather`, выполните `/newbot` и получите token. Не публикуйте его и не добавляйте в Git.
2. Откройте `https://<ваш-домен>/admin/telegram` и вкладку «Настройки».
3. Вставьте token, выберите `Webhook` для production, заполните тексты и выберите ручной либо автоматический режим цены Stars для каждого включённого тарифа.
4. Если сервер не может напрямую открыть `api.telegram.org`, выберите `Автоматически` или `Только SOCKS5`, добавьте до 10 маршрутов в порядке приоритета и укажите credentials. Пароли после сохранения больше не возвращаются в браузер.
5. Включите переключатель и нажмите «Сохранить и настроить».
6. ProxyHarbor последовательно проверит маршруты через `getMe` и сам применит профиль, встроенный аватар, команды и HTTPS webhook. В настройках показываются превью аватара, статус и время последнего успешного применения; username и итоговый webhook появятся на вкладке «Обзор».
7. Откройте бота, отправьте `/start`, затем проведите тестовую покупку отдельным тестовым тарифом либо минимальной согласованной ценой.

Для webhook `TelegramBot__PublicBaseUrl` должен быть публичным HTTPS origin без path, например `https://proxy.blagodaty.ru`. В Docker Compose он получает `${PUBLIC_HOST}` автоматически. Long polling подходит для локальной разработки без входящего HTTPS.

## Способы оплаты и подписки

Команда `/buy` сначала показывает тарифы в основной валюте каталога, а после выбора — все доступные способы. Метод появляется в Telegram только когда он включён и его обязательные реквизиты полностью заполнены в `/admin/payments`. Отключение шлюза в админке сразу убирает его из новых Telegram-покупок.

Stars оплачиваются встроенным Telegram invoice. Для остальных провайдеров бот создаёт тот же `PaymentOrder`, что и сайт, и отправляет inline-кнопку на HTTPS hosted checkout. Цена, срок и тариф всегда берутся из серверного каталога; callback Telegram не может подменить сумму. Подписка активируется общим обработчиком подписанного webhook провайдера, поэтому история и статус заказа едины для сайта и бота.

### Telegram Stars

Сначала создайте/включите тарифы в `/admin/payments`, затем выберите режим цены в `/admin/telegram`:

- **автоматически** — рублёвая цена подписки делится на настраиваемый ориентир `Цена 1 Star, ₽`, после чего всегда округляется вверх до выбранного шага;
- **вручную** — фиксированная цена Stars не зависит от последующих изменений основного тарифа;
- режим выбирается отдельно для каждого продукта, поэтому автоматические и ручные цены можно безопасно сочетать.

По умолчанию используется ориентир `1,68 ₽/Star` и шаг `5`. Поэтому тарифы `99 ₽`, `350 ₽`, `690 ₽` и `1 890 ₽` автоматически превращаются в `60 ⭐`, `210 ⭐`, `415 ⭐` и `1 125 ⭐`. Округление вверх исключает случайное уменьшение заданной стоимости. Уже существующие ручные цены не переключаются автоматически без решения администратора.

Ориентир является прозрачным бизнес-правилом ProxyHarbor, а не «официальным курсом»: Telegram предупреждает, что стоимость приобретения Stars может различаться из-за платформы, VAT и других сборов и не предоставляет Bot API для единого преобразования рублёвой цены тарифа в Stars. Минимальный пакет пополнения также может быть больше конкретного счёта; остаток сохраняется на балансе пользователя. Поэтому точное равенство фиатной суммы для каждого пользователя гарантировать нельзя, а ориентир можно изменить в админке без выпуска новой версии. Официальные требования: [Telegram Stars payments](https://core.telegram.org/bots/payments-stars) и [Bot API](https://core.telegram.org/bots/api#sendinvoice).

Для Stars API отправляет пустой `provider_token`, валюту `XTR` и ровно одну price line. Сумма и payload повторно проверяются перед подтверждением checkout. Подписка меняется только по `successful_payment`; повторный update или `telegram_payment_charge_id` не создаёт второе продление.

Заказы Stars видны в общем реестре оплаты с provider `telegram_stars`. Карточные реквизиты не участвуют в этом потоке и ProxyHarbor их не получает.

## Юридическое подтверждение и рассылки

Новый и ранее не подтвердивший документы пользователь сначала получает две независимые кнопки: принятие текущей публичной оферты и отдельное согласие на обработку персональных данных. Сервер сохраняет редакцию и время каждого действия; до обоих подтверждений покупка, кабинет и выдача прокси недоступны. Ссылки строятся из доверенного `TelegramBot__PublicBaseUrl`.

Команда `/notifications` разделяет договорные сервисные уведомления и рекламные сообщения. Реклама по умолчанию отключена. Включение рекламы записывает редакцию и время отдельного согласия, отключение — время отзыва. Административная массовая рассылка выбирает только чаты с действующим согласием; личные ответы поддержки и необходимые сообщения об оплате от него не зависят.

Поверх пользовательского согласия действует deploy-предохранитель `TelegramBot__MarketingBroadcastsEnabled` (`TELEGRAM_MARKETING_BROADCASTS_ENABLED` в Compose). Его безопасное значение — `false`: кнопка согласия и поле рассылки недоступны, а сервер отклоняет broadcast с `409`. Включать флаг можно только после документированной правовой квалификации сервиса и конкретной рекламной кампании; согласие пользователя не отменяет категориальные запреты закона о рекламе.

## CRM и рассылки

Вкладка «CRM и сообщения» показывает связанные Telegram-чаты с серверной пагинацией и поиском. В диалоге видны входящие сообщения, автоматические ответы и ответы администратора. Можно отключить напоминания или пометить чат заблокированным.

Broadcast создаёт отдельные задания только для незаблокированных чатов с включёнными уведомлениями. HTTP-запрос не ждёт доставки всей рассылки; worker отправляет её с лимитами Telegram, повторяет временные сбои и сохраняет результат каждой доставки.

## Безопасность

- token и webhook secret шифруются ASP.NET Data Protection перед сохранением в PostgreSQL;
- адреса, логины и пароли SOCKS5 находятся в том же зашифрованном secret payload; публичный и admin GET возвращают только безопасную метаинформацию и признак сохранённого пароля;
- GET admin API никогда не возвращает token или secret, только `tokenConfigured`;
- token не пишется в application logs и находится только в path запроса к официальному `api.telegram.org` через клиент с отключённым HTTP logging;
- webhook ограничен 1 MiB, rate limit, bot username и constant-time проверкой secret header;
- все admin endpoints требуют роль Administrator или automation API key;
- входящий пользовательский текст имеет предел 4096 символов, а update дедуплицируется по `update_id`.

Сохраняйте Data Protection volume и его независимую копию: Telegram-конфигурация в PHB3 остаётся зашифрованной и без этих ключей не восстановит token. Token доставки backup (`TELEGRAM_BOT_TOKEN`) не используется commerce-ботом и по-прежнему хранится только как Docker secret.

## Диагностика

На вкладке «Обзор» отображаются пользователи, MAU за 30 дней, число включённых уведомлений/блокировок, успешные Stars-платежи, выручка, pending и failed задания. Кнопка «Применить заново» повторно устанавливает профиль, команды, изображение и transport без замены token.

Если Telegram отвечает `429`, задание остаётся в очереди до указанного `retry_after`. При `5xx` применяется exponential backoff. При `403` чат помечается заблокированным. Failed после исчерпания попыток остаётся доступным для операторской диагностики; успешные задания очищаются через 90 дней, receipts update — через 30 дней.

## Основные endpoints

| Метод | Endpoint | Назначение |
|---|---|---|
| `GET/PUT` | `/api/v1/admin/telegram` | Безопасное чтение и полная настройка |
| `GET` | `/api/v1/admin/telegram/avatar` | Превью встроенного аватара для админки |

| `POST` | `/api/v1/admin/telegram/messages` | Личный ответ или broadcast |
| `POST` | `/api/v1/telegram/webhook/{username}` | Защищённый публичный webhook |
