# Распределённая проверка прокси

ProxyHarbor может проверять очередь прокси на любом количестве внешних Linux VPS. Основной сервер остаётся control plane и единственным владельцем PostgreSQL, а checker-агенты устанавливают только исходящие HTTPS-соединения к нему. Открывать на checker-хостах новый входящий порт не требуется.

## Подключение узла

1. Опубликуйте образ `ghcr.io/xsenus/proxyharbor-checker-agent:latest` либо задайте собственный `CHECKER_AGENT_IMAGE`.
2. Установите `CheckerAgentDeployment__PublicBaseUrl` в корневой HTTPS origin основного сервиса, например `https://proxy.example.com`.
3. Откройте в панели **Узлы проверки**, нажмите **Добавить VPS** и укажите имя, публичный IP, SSH-порт, пользователя, пароль, concurrency и размер партии.
4. Основной сервер выполняет одноразовое SSH-подключение, проверяет host key, при необходимости устанавливает Docker и запускает изолированный контейнер `proxyharbor-checker-agent`.
5. Дождитесь первого heartbeat и состояния **На связи**.

SSH-пароль существует только в теле текущего административного запроса: он не сохраняется в БД, backup, ответах API или конфигурации контейнера. Агент получает случайный токен; в PostgreSQL хранится только SHA-256 hash, а plaintext находится на checker-хосте в файле с режимом `0400`. При повторном развёртывании token ротируется только после успешного запуска нового контейнера.

Первое подключение использует trust on first use. Сохранённый SHA-256 fingerprint блокирует последующее подключение к хосту с заменённым SSH-ключом. После легитимной переустановки VPS удалите старую запись с подтверждённого хоста и создайте её заново.

## Как распределяется работа

- агент отправляет heartbeat и атомарно запрашивает партию;
- PostgreSQL выбирает только просроченные задания через `FOR UPDATE SKIP LOCKED`;
- партия получает UUID lease и ограниченный срок;
- агент периодически продлевает lease во время проверки и загрузки результата;
- control plane принимает результат только от владельца действующей lease и только с полным, точным набором элементов;
- запись результатов и завершение audit run выполняются согласованно;
- локальный валидатор основного сервера продолжает забирать свободную очередь как резервный исполнитель.

Две ноды не получают один и тот же прокси одновременно. Поздний результат старой lease не может перезаписать более свежую проверку.

## Отказы и восстановление

Если checker-контейнер, VPS или сеть исчезли, lease автоматически истекает, незавершённый validation run помечается ошибкой, а вся партия возвращается в общую очередь. Другой агент или локальный валидатор заберёт её без ручного вмешательства. Остановка одного узла не останавливает сбор, API и остальные проверки.

Если недоступен control plane, агент не теряет уже рассчитанный результат: он продолжает heartbeat/upload с bounded retry и экспоненциальной задержкой. После истечения lease сервер отклонит устаревшую отправку, а партия будет безопасно проверена заново.

Если PostgreSQL временно недоступен, выдача новых lease прекращается; данные не подтверждаются частично. После восстановления базы обычный цикл продолжается.

## Настройка производительности

- **Concurrency** — число параллельных сетевых проб внутри агента. Начните со 100–200 и повышайте только после проверки CPU, RAM, NAT/conntrack и лимита файловых дескрипторов.
- **Размер партии** — сколько прокси арендуется за цикл. Практический старт: примерно `2 × concurrency`.
- Размещайте узлы в разных сетях и странах: это снижает влияние локальной маршрутизации и блокировок.
- Не запускайте несколько записей админки на одном VPS: установщик намеренно управляет одним контейнером с фиксированным именем.

## Эксплуатация

Панель показывает heartbeat, текущую lease, версию агента, удалённый IP, ошибки и накопительные счётчики. Узел можно приостановить без удаления; уже взятая партия либо завершится, либо вернётся после TTL. Кнопка повторного развёртывания требует SSH-пароль, проверяет прежний fingerprint и ротирует agent token.

Удаление сначала удаляет именованный контейнер и token-файл с VPS и только затем центральную запись. При недоступном VPS запись сохраняется, чтобы не создавать ложное ощущение, что секрет удалён удалённо.

В backup v7 входят настройки и аудит узлов, но не входят SSH-пароли и agent-токены. После disaster recovery выполните повторное развёртывание каждого узла.

## Ограничения автоматической установки

Автоустановка Docker поддерживает Debian/Ubuntu-хосты с `apt-get` и systemd. На другом дистрибутиве установите Docker заранее. SSH-пользователь должен быть root, потому что агенту требуется создать `/opt/proxyharbor-checker` и системный контейнер. Установщик не изменяет другие контейнеры, каталоги или опубликованные порты.
