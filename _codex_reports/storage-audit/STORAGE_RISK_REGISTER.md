# Реестр рисков хранения ProxyHarbor

Срез: 2026-09-22, baseline `main@cafb95c`. Наличие плана не меняет статус риска: все риски ниже остаются открытыми до выполнения связанных задач и acceptance gates.

| RISK-007 | HIGH | Per-copy state | Потерянный ответ после PUT/Telegram send или crash между upload и DB update даёт UNKNOWN outcome. | RISK-008 | MEDIUM | Scheduler/RPO | Каждый failed run создаёт новый snapshot через 15 минут, хотя ранее S3 мог уже подтвердиться; возможны лишний CPU/DB I/O и копии. Permanent Telegram size rejection ждёт полный interval. | EVID-010–013 | Locks, retention, persisted schedule anchor. | TASK-031: отделить snapshot от copy delivery, повторять недостающую delivery job, не пересоздавая bytes; bounded retry/backoff. | Новый snapshot всё равно нужен по следующему RPO interval. | OPEN |
| RISK-009 | MEDIUM | Telegram backup channel | До 20 отдельных сообщений; partial external delivery возможна, собрать/удалить orphan parts автоматически нельзя. Размер ограничивает применимость канала. | EVID-014, EVID-048 | Audit success только после всех частей; adapter переводит partial send в UNKNOWN и удаляет local temporary parts; join tool валидирует набор. | TASK-030/033: явный secondary/best-effort policy и manual-review для ambiguous multipart; message IDs недоступны через текущий transport. | Telegram не становится полноценным immutable object archive. | PARTIALLY MITIGATED LOCALLY |
| RISK-010 | HIGH | Restore availability | Локальный/CI restore работает, но production restore из последней offsite copy и запуск бизнеса после потери VPS не подтверждены. | EVID-015–016, EVID-024 | Transaction, exclusive lease, integrity validator, CI local drill. | TASK-041, TASK-062: isolated environment drill from remote verified copy, DP keys/secrets, business checks, measured RTO/RPO. | Provider-scale outage и unavailable operator remain DR risks. | OPEN / NOT VERIFIED |

Это rollback artifact, не independent DR copy. | EVID-022 | `0600`, safe atomic publication, `pg_restore --list`, bounded retention. | TASK-043: классифицировать как short-lived local rollback artifact; при необходимости зашифровать/offsite-deliver отдельной policy или удалить после verified PHB3 checkpoint. | Host root compromise видит dump до encryption; минимизировать lifetime. | OPEN |
| RISK-012 | MEDIUM | Operations/alerts | Нет метрик per-destination success/debt/UNKNOWN, remote restore readiness, independent copy count, S3 health и key drill age. | RISK-013 | HIGH | Local DB/backups/keys | PostgreSQL, local backups, DP keys and app run on one VPS/Compose host. ## Приоритет

1. Немедленно закрыть RISK-001/RISK-003: backup format v8 и exhaustive restore test.
2. До заявления DR-ready закрыть RISK-002/RISK-004/RISK-006/RISK-010/RISK-013/RISK-016.
3. Затем включать automatic destination fallback: RISK-005/RISK-007/RISK-008/RISK-014/RISK-019/RISK-020.
4. Наблюдаемость и эксплуатационные controls: RISK-009/RISK-011/RISK-012/RISK-015.
5. RISK-018 — отдельная инфраструктурная программа; не блокирует исправление backup, но ограничивает runtime availability.
